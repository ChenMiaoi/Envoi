# Local conversation statistics

The chart icon next to chat history opens statistics on demand in both project and paper chats. The default scope is the whole conversation; the latest turn can be selected separately. Per-turn details keep model identity visible when a conversation switches models. Collection does not require opening the panel and makes no additional inference requests. Metrics are saved with the assistant's local conversation record when the turn settles and restored with history.

A conversation turn is one user request and its agent response. Each SDK `turn_start` begins a model phase, ending at its assistant `message_end`; a conversation turn may contain several such phases. Tools are counted by execution IDs. Model phase duration includes SDK preparation, network and provider waiting. Tool time sums each execution's elapsed time, so parallel tools can overlap. Overall task elapsed time sums turn durations and excludes idle time between user requests.

First-output latency runs from model phase start to the first nonempty text, thinking or tool-argument delta. Average generation speed is the sum of reported output tokens divided by the sum of first-output-to-completion durations for completed calls that have both measurements; it includes reasoning tokens and is an observed streaming rate, not a pure decoding benchmark. Unreported calls do not contribute to token totals or this rate.

SDK-normalized input is uncached input + cache reads + cache writes. Cache-read share is cache-read tokens / total input, weighted over calls reporting usage. The SDK initializes absent usage to all zeroes, so all-zero usage is treated as unavailable. Because the SDK may also initialize unreported cache data to zero, a positive cache-read report is required before displaying a ratio; otherwise the panel says unavailable rather than asserting 0%. Coverage displays measured turns and calls reporting usage. Older records are not retroactively estimated. Interrupted records without a final snapshot stop at their last observed timestamp; data lost before persistence cannot be reconstructed.

No prices or billed costs are inferred. Manual models receive the neutral cost object required by the SDK to parse usage, but those placeholder amounts are never shown as financial data. The exported JSON contains numeric statistics, model/provider identifiers, tool names, call IDs and timestamps, with no prompts, reasoning text, tool arguments/results or credentials. It exports the selected scope.

Validation: `test-chat-metrics.mjs` verifies timing, concurrent tools, missing usage, cache math, cancellation and content-free persistence. `test-agent-native.mjs` exercises actual SDK loopback usage/first-output persistence, including manual models. The desktop chat regression checks scope selection, rendering and export without writing into the user's Downloads folder.
