# 论文库多来源在线检索调研与方案

调研日期：2026-09-11  
状态：初步调研与方案讨论，尚未实现或完成 API 联调

## 目标与范围

在 Envoi 论文库中直接搜索相关论文，覆盖尽可能多的学科、出版社、会议和开放仓储。用户可以查看摘要与出版信息、加入当前项目论文库，并在存在可用开放全文时下载 PDF 阅读。

覆盖目标不能局限于 arXiv 等预印本平台。默认搜索应同时包含正式出版论文与预印本，也应允许检索没有开放全文的论文，避免遗漏重要研究。“仅开放全文”作为可选筛选项。

本功能包含关键词检索，以及后续基于已有论文寻找相关研究的能力。本文不承诺复现 Google Scholar 的全部索引与排序，也不将搜索结果可见等同于全文可下载。

## 核心结论

1. 采用多个综合学术索引联合检索，再用专业来源补充覆盖。OpenAlex、Semantic Scholar、Crossref 本身跨越许多出版社，接入它们并不意味着仅覆盖三个网站。
2. ACM 等出版社论文可以先通过综合索引检索，保留原始出版页面和全文位置；是否需要直接接入出版社，应由实测遗漏率决定。
3. Google Scholar 存在第三方开源抓取库，但缺少适合本功能的公开官方搜索 API，不宜作为默认检索后端。
4. 优先在现有 TypeScript／Node 架构中调用官方接口。Python 开源库可作为实现参考，不必为简单 HTTP 接口额外引入 Python 运行环境。
5. 接入网站数量不是覆盖率指标。需要通过跨学科、跨出版社的样本集验证检索召回、元数据完整度、版本关系和全文获取情况。

## 已调研的来源

以下结论来自官方文档或项目仓库阅读，尚未进行实际请求和稳定性测试。服务额度、价格与条款可能变化，实施前应再次核实。

| 来源                | 已确认的能力                                     | 建议定位                          | 注意事项                                                                                                |
| ------------------- | ------------------------------------------------ | --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| OpenAlex            | 综合论文搜索、实体筛选、作者及发表来源等关联信息 | 默认综合检索源                    | 存在免费使用额度及 API Key 机制；搜索与普通筛选请求成本不同，不能假设无限免费                           |
| Semantic Scholar    | 论文搜索、引用关系、独立的相关推荐 API           | 联合检索及后续相关论文发现        | 需要限流与重试；官方介绍的初始 Key 额度为每秒 1 次请求，部分端点需要认证                                |
| Crossref            | 出版社提交的 DOI 元数据查询和搜索                | 正式出版信息检索、DOI 补全与校验  | 元数据质量取决于提交内容，不保证有摘要或全文                                                            |
| arXiv               | 官方论文检索 API 及预印本访问                    | 专项检索源，补充较新的预印本      | 遵守接口请求间隔与并发规则；预印本与正式版不能无条件合并                                                |
| Unpaywall           | 根据 DOI 查询开放获取位置                        | 检索后的全文定位                  | 不是主要关键词搜索源；API 要求 email 参数并有调用限制                                                   |
| Google Scholar      | 网页搜索、相关论文、引用导出                     | 外部搜索补充入口                  | 官方限制自动抓取搜索结果，不提供批量访问；抓取库存在验证码、封禁及网页变化风险                          |
| ACM Digital Library | ACM 自己出版研究的开放全文访问                   | 通过综合索引发现，链接至 ACM 原文 | ACM 从 2026 年 1 月起全面开放获取；本轮未确认到适用的公开通用搜索 API，不能将开放阅读理解为无限自动访问 |

ACM Digital Library 中索引的其他出版社内容，不应一概标记为开放全文。搜索来源、正式出版社、全文托管位置应分别保存与展示。

对每个来源选择以下接入方式之一：直接调用公开 API；同步允许使用的公开元数据并建立索引；由综合索引覆盖；仅提供外部搜索入口。不能将这四种方式都展示成已经实现的原生联合搜索。

## 产品交互建议

论文库增加“在线搜索”入口，与当前项目内的本地筛选明确区分。

1. 用户输入关键词，默认联合检索所有已启用的原生来源。
2. 可按年份、来源、出版社／会议、学科和开放全文状态筛选。各来源不支持的过滤条件应明确处理，不能静默当作已生效。
3. 结果逐步展示，不等待最慢来源。显示标题、作者、年份、发表来源、摘要（若有）、发现来源、全文状态和“已入库”标记。
4. 点击结果可查看详情，并选择“加入论文库”或“加入并获取 PDF”。没有 PDF 也可以保存文献信息。
5. 一个来源失败时，其他结果仍然可用，并显示未完成检索的来源与重试入口。
6. 提供“在 Google Scholar 搜索”等外部入口，明确这会打开外部页面。
7. 后续增加“寻找相关论文”，基于所选论文的标识调用推荐或引用关系服务。

不要将未知全文状态显示为“无开放全文”，也不要将某个来源搜索失败显示为“没有论文”。引用次数必须保留来源，不直接相加。

## 技术方案建议

### 搜索与入库分离

建议增加独立搜索服务，在可信 Node／Electron 一侧调用外部接口。搜索结果先进入短期缓存，用户选择后才进入项目论文库，避免搜索产生大量持久化文献。

每个来源适配器声明支持的能力，包括关键词搜索、详情获取、分页、过滤和相关论文推荐。统一接口返回标准化结果、来源自己的分页游标、是否还有下一页及错误信息。

API Key 不应作为产品共享秘密写入桌面安装包。第一阶段可支持用户配置个人 Key；如未来使用统一代理服务，需要另行设计运营成本、缓存、额度与隐私策略。

### 统一数据与去重

建议结果保留：标题、作者、日期／年份、摘要、期刊或会议、出版社、DOI、arXiv ID、各来源 ID、出版页面、全文候选位置、开放状态、版本类型、字段来源和获取时间。

优先使用规范化 DOI 和 arXiv ID 匹配。标题、作者和年份只用于辅助识别；存在疑问时保留候选关联，不自动合并。预印本和正式出版版本应能关联，但不丢失版本信息。

多个来源的相关性分数不可直接比较。初步可以采用基于来源排名的融合方式，并用真实查询评估效果。合并后的结果数量不能简单累加各来源总数。

### 全文获取

检索结果中的全文位置、Unpaywall 返回的位置和出版页面是不同类型的链接。优先使用明确的可用 PDF 地址，失败时保留原文入口和元数据。不能把 HTML 页面、登录页或错误页面作为 PDF 保存。

开放阅读不必然意味着允许再分发或任意批量下载；保存可获得的许可证和版本信息，并遵守来源规则。

### 稳定性

每个来源独立设置超时、并发和节流策略，遵循服务端重试提示。支持取消旧查询、请求缓存、失败后退避和部分结果返回。直接 API 的实测应包含桌面运行环境及目标用户网络环境。

## 与现有 Envoi 的衔接

现有代码已有可复用基础：

| 位置                              | 当前能力                                           | 建议扩展                                |
| --------------------------------- | -------------------------------------------------- | --------------------------------------- |
| `app/src/views/LibraryView.tsx`   | 论文库展示与导入入口                               | 增加在线搜索与结果详情                  |
| `app/src/lib/paperMetadata.ts`    | 标识识别、Crossref／DataCite 字段转换、BibTeX 生成 | 接收标准化搜索结果，保留来源与版本      |
| `app/server/paper-download.mjs`   | HTTPS PDF 下载、超时、大小和内容检查               | 接收解析后的 PDF 候选地址，报告失败原因 |
| `app/server/research-library.mjs` | 项目级元数据、附件、笔记与阅读状态                 | 复用入库／附件流程，完善跨来源标识匹配  |
| `docs/research-library.md`        | 论文库数据与文件映射说明                           | 实施后补充在线入库的数据约定            |

现有附件哈希和引用键去重不能替代跨来源 DOI／版本识别，需要单独设计。无需重做现有 PDF 阅读器和笔记系统。

## 建议实施阶段

### 阶段一：验证广覆盖方案

对 OpenAlex、Semantic Scholar、Crossref 做真实接口验证，同时评估 DBLP、arXiv 与 OpenReview 的补充价值。确认鉴权、费用、限流、摘要和全文字段。此阶段产出来源能力矩阵和覆盖测试记录，再确定默认启用组合。

### 阶段二：实现综合检索闭环

接入验证通过的综合来源及高价值专项来源，完成联合检索、去重、部分失败展示、详情、元数据入库和开放 PDF 获取。首版验收必须覆盖多个出版社的正式出版物，不能以仅支持 arXiv 检索作为完成标准。

### 阶段三：补齐遗漏与相关论文发现

根据实测遗漏加入专业仓储或会议元数据索引，随后实现相关论文推荐、引用追踪和版本关联。需要索引同步或付费权限的来源单独排期。

## 覆盖与质量验证计划

建立已知论文集合和主题查询集合，包含 ACM、IEEE 等正式会议／期刊论文、不同学科、较新论文、经典论文、非英文文献、有／无 DOI、预印本与正式版、开放与非开放全文。

记录每个来源及联合检索的以下结果：

- 已知论文是否找到，以及位于前多少条结果。
- 主题查询前若干条结果的人工相关性判断。
- 标题、作者、年份、DOI、摘要的完整性及正确性。
- 每个新增来源带来的独有有效结果。
- 重复记录及预印本／正式版的误合并情况。
- 开放全文候选的实际可访问率与 PDF 下载成功率。
- 首批结果延迟、整体耗时、限流和失败情况。
- 普通查询与翻页查询的调用量及费用。

测试阈值在取得基线后确定，不预先承诺未经测量的覆盖率。本文尚未包含实测结果。
